# 章悟式∞競輪OS 2方式3PDF API

同じレース前3PDFを一度だけ正規化し、男子競輪の2車単を2つの独立方式で計算します。

## 2つの方式

### しょーご式：固定5点

1. 選手個人能力
2. 役割適性（先頭・番手・3番手以降・単騎）
3. ライン補正
4. 展開シナリオ
5. 10万回シミュレーション
6. 能力確率から保守EVを算出
7. 保守EV上位5点を採用

### 市場残差システム：固定3点

しょーご式と同じ10万回能力確率と、2車単オッズから作った市場確率を次の式で混合します。

```text
市場確率 ×（能力確率 ÷ 市場確率）^ λ
```

混合確率を正規化し、さらに固定シードで10万回再計算した後、保守EV上位3点を採用します。

- λ=0: 市場確率のみ
- λ=0.5: 市場と能力の幾何平均（初期値）
- λ=1: 能力確率のみ

両方式の買い目は混ぜて再計算しません。共通買い目は表示のみです。

## 固定対象

- 男子競輪のみ
- 券種は2車単
- 女子・ガールズ・L級は `WOMEN_EXCLUDED / NO_BET`
- レース結果・払戻・レース後データ・Web自動取得は予測に使用しない
- 同じ入力とλなら同じ結果

## 入力

1. netkeirin 出走表PDF
2. KEIRIN.JP「着度数・H・S回数」PDF
3. KEIRIN.JP 2車単オッズPDF
4. EXデータ画像は任意

3PDFの開催場・日付・レース番号を照合し、選手、H/B、並び、全2車単オッズが揃ってから計算します。KEIRIN.JPオッズは「○番車 全選択」の列を座標で読み、7車なら42通り、9車なら72通りが揃わない限り停止します。締切後のオッズPDFは `POST_RACE_SOURCE / NO_BET` で拒否します。

空ファイル、破損PDF、別レース混在、欠損があれば `INPUT_ERROR / NO_BET` で安全停止します。

## 起動

```bash
docker compose -f docker-compose.individual.yml up --build
```

- 稼働確認: `GET http://localhost:8787/health`
- PDF予測: `POST http://localhost:8787/analyze`

## 主な出力

- 主導権候補・本命ライン・展開シナリオ
- `strategies.shogo.candidates`: しょーご式5点
- `strategies.residual.candidates`: 市場残差3点
- `common_candidates`: 2方式の共通買い目
- `dual_pair_probabilities`: 全2車単の能力・市場・残差確率とEV
- `pdf_audit.odds_source`: `KEIRIN.JP`
- PDF照合監査

## 回帰テスト

- しょーご式が5点を返す
- 市場残差が3点を返す
- 7車で全42通りを返す
- KEIRIN.JPのページまたぎオッズ表を読み取る
- 締切後のKEIRIN.JPオッズを拒否する
- λ=0で残差理論確率が市場確率と一致
- λ=1で残差理論確率が能力確率と一致
- 女子競輪を拒否
- 同一入力で同一結果

現行版: `1.2.0-dual-strategy`
